# Search & Favourites

**Repository → Search** finds records across your library.

## What is searchable

| | Searchable when |
|---|---|
| Title, type, classification, tags | Always — set at filing |
| Filing location | Always |
| **Document content** | After [OCR](/dms/ocr-ai) has processed it |

That last row is the one to remember. A freshly imported scan is findable by its
*metadata* immediately, but not by the words inside it until OCR has run. If a search for
text you know is in a document returns nothing, check the OCR queue before concluding the
document is missing.

## Saved searches

A search you run repeatedly can be saved and re-run. Useful for the standing questions —
everything in a bin, everything of a type due for review, everything filed this month.

Saved searches are also the practical way to make a records report repeatable: run the same
saved search each period rather than reconstructing the filters from memory.

## Favourites

**Repository → Favorites** lists records you have starred. Different purpose from a saved
search: a favourite is a specific document you keep returning to, a saved search is a
question you keep asking.

<Callout type="info">
  Documents you cannot access do not appear in results. If a colleague can find something
  you cannot, the difference is
  [permissions or confidentiality](/dms/permissions), not the search.
</Callout>

## Making records findable

Three things at filing time determine whether something is findable later:

1. **A title someone would actually type** — not the scanner's filename
2. **The right type and classification** — these are the filters people narrow by
3. **Tags for the cross-cutting things** a classification cannot express — a project name,
   a counterparty

Tags are worth using sparingly and consistently. Fifty tags applied once each help nobody;
five applied to everything relevant are what turn up the set you wanted.
